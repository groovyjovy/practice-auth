# 壊してみる実験

実験: `$ARGUMENTS`(空なら現在のフェーズの未実施の実験を一覧して選んでもらう)

これはローカルの学習用環境(`localhost` / `*.local`)に対する実験に限る。外部のホストを対象にしたスクリプトは作らない。

## 手順

1. **仮説を立てさせる**:実験を始める前に本人に問う
   - 「この攻撃が成功するには、どんな条件が必要だと思う?」
   - 「成功したら何が観測できるはず?」
2. **脆弱性の仕込み**:本人のコードにどんなバグ / 設定を入れればよいかを **言葉で** 指示する(例:「検証関数でヘッダの `alg` を読んで分岐するようにしてみて」)。本人のコードは Claude が書き換えない
3. **攻撃側の用意**:Claude が `attacks/phase<n>-<name>/` に作ってよい
   - 攻撃スクリプト(TypeScript / シェル / curl)
   - 攻撃者ページ(XSS / CSRF 用の HTML)
   - 必要なら攻撃者サーバー(`evil.local` など。`/etc/hosts` への追加は本人に依頼する)
   - 各ファイル冒頭に「何を狙う攻撃か」「前提条件」をコメントで書く
   - 依存パッケージが必要なら追加はせず、本人にインストールを依頼する(なるべく Node 標準 + `fetch` で済ませる)
4. **実行と観察**:実行手順を本人に示し、実行は本人が行う。DevTools / curl -v のどこを見ればよいかを伝える
5. **振り返り**:結果を見て問う
   - 「なぜ成功(失敗)した?」
   - 「どの 1 行を直せば防げる? それはどの仕様のどの節に書いてある?」
   - 対策の実装は本人に任せ、終わったら同じ攻撃を再実行して防げたことを確認させる
6. `PROGRESS.md` の実験欄にチェックを入れ、ログに一行追記する

## 実験ごとのメモ

- **XSS で Cookie 窃取**:攻撃者が値を受け取る受信サーバーが別ホストに要る。`HttpOnly` の有無で `document.cookie` の中身がどう変わるか
- **CSRF**:SameSite の既定値(Lax)はブラウザ依存なので、明示した値ごとに挙動を比べる。localhost はポート違いでも same-site
- **ブルートフォース**:試行回数 / 時間を計測させ、scrypt のコストとレート制限がどう効くかを数字で見る
- **`alg: none`**:ヘッダ `{"alg":"none"}`、署名部が空の JWT を作る
- **ログイン CSRF(state なし)**:攻撃者が自分の認可コードで止めたコールバック URL を被害者に踏ませる
- **redirect_uri 前方一致**:`/etc/hosts` に `client.local:3000.evil.local` 相当のホストは書けないので、パス前方一致(`/callback` → `/callback/../evil`)やサブドメインなど再現可能な形に置き換えて設計する
- **PKCE なし**:横取りしたコードだけで `/token` を叩く
