# 口頭試問

対象: `$ARGUMENTS`
- 数字:そのフェーズのチェックリスト
- `weak`:`PROGRESS.md` で `[ ]` / `[~]` の項目から出題
- `all`:全フェーズから横断でランダム
- 空:現在のフェーズ

## 進め方

1. `memo.md` と `PROGRESS.md` を読み、出題する項目を選ぶ(指定がなければ 3 問)
2. **1 問ずつ** 出す。一度に複数出さない。チェックリストの文言をそのまま読み上げず、具体的な場面に置き換えて聞く
   - 例:「`timingSafeEqual` を使う理由」→「ログイン処理で、ハッシュ同士を `===` で比べていたとする。攻撃者はどうやってこれを悪用できる?」
3. 本人の回答を待つ。回答後に評価する:
   - **合格 `[x]`**:攻撃(または問題)と対策の因果を自分の言葉で説明できた
   - **部分的 `[~]`**:キーワードは出たが因果が曖昧、または一部欠けている
   - **不合格 `[ ]`**:説明できなかった
4. 評価の後に、**足りなかった部分だけ** を補足する。合格なら深掘りの追加質問を 1 つ(「では SameSite=Lax でも防げない CSRF は?」など)してもよい
5. 本人が書いたコードがあれば、「あなたのコードの `path:line` ではどうなっている?」と実装と結びつける質問を混ぜる
6. 全問終わったら:
   - `PROGRESS.md` の該当項目の記号を更新する
   - 「ログ」に `- YYYY-MM-DD /quiz phase<n>: 合格 x / 部分 y / 不合格 z(弱点: ○○)` を追記する
   - 弱点に対応する仕様の節か実験を 1 つ勧める

## 注意

- 回答を誘導しない。ヒントを求められたら「答え」ではなく「考える切り口」を出す
- 本人が「分からない」と言ったら、すぐ答えを言わず、もう一段簡単な問いに分解して 1 回だけ再挑戦させる
