# フェーズ開始

引数: `$ARGUMENTS`(フェーズ番号。`next` や空なら `PROGRESS.md` の「現在のフェーズ」の次)

## 手順

1. `memo.md` の該当フェーズと `PROGRESS.md` を読む
2. 前のフェーズに未合格のチェック項目が残っていれば、一言だけ触れる(進むかどうかは本人が決める)
3. 以下を簡潔に提示する。**コードは一切書かない**
   - **このフェーズのゴール**(1〜2 文。何が「腹落ち」すれば終わりか)
   - **作るもの** を小さなステップに分解した順序案(各ステップは「動作確認できる単位」にする)
   - **最初の一歩**:ステップ 1 で本人が調べるべきこと・決めるべきこと
   - **環境構築の観点**(必要な場合):必要なパッケージ名、どの公式ドキュメントのどのページを見るか、設定で迷いそうな論点。コマンドそのものは書かず「何をするコマンドが必要か」まで
   - **先に読むとよいもの**:補助教材や仕様の節(多くても 2 つ)
4. 最後に「このフェーズを始める前に、今の時点でどう理解しているか」を 1 問だけ問いかける(事前の理解を記録し、終了時と比較するため)
   - **3 で提示した内容から答えが読み取れる問いにしない。** ステップの説明に書いた仕組みそのものではなく、「なぜ」「どう破られるか」など一段先を問う
5. `PROGRESS.md` の「現在のフェーズ」を更新する

## フェーズ 0(環境構築)の場合

**フェーズ 0 は軽く済ませる。** 本人の目的は認証・認可(特に OAuth / OIDC)の理解であり、環境構築の知識を深掘りすることではない。問いかけは下記の論点に留め、回答への追加の深掘り(Node のバージョン管理方式、`engines` の仕様など)はしない。詰まっているときだけ手助けする。

memo.md の「技術スタック」を元に、次の論点を **問いかけ形式で** 提示する:

- Node.js のバージョン管理をどうするか(Active LTS とは何か、どこで確認するか)
- pnpm workspace にするか単一パッケージにするか(フェーズ 3 で client / auth / api の 3 サーバーになることを踏まえて)
- `minimumReleaseAge` は何を防ぐ設定か(サプライチェーン攻撃との関係)
- TypeScript を Node で直接実行する方法の選択肢(tsx / Node の type stripping など)と、それぞれのトレードオフ
- `strict: true` で有効になるフラグ

本人が手を動かした後に `/check` で設定ファイルを見る流れにする。
