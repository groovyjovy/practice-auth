# シーケンス図の添削

対象: `$ARGUMENTS`(ファイルパス、または貼り付けられた Mermaid。番号なら `memo.md` の「仕上げ」の図)

図は Claude が描かない。添削のみ行う。

## チェック観点

1. **登場人物**:必要な参加者が揃っているか(例:認可コードフローならブラウザ / Client / AS / RS の 4 者 + Resource Owner)
2. **順序**:ステップの抜け・順序の誤り
3. **チャネル**:フロントチャネル(ブラウザ経由のリダイレクト)とバックチャネル(サーバー間通信)を区別できているか
4. **パラメータ**:すべての矢印にパラメータが書かれているか(`response_type`, `client_id`, `redirect_uri`, `scope`, `state`, `code_challenge`, `code_challenge_method`, `code`, `code_verifier`, `nonce`, `Set-Cookie` の属性など)
5. **注記**:各パラメータに「何を防いでいるか」が書かれていて、それが正しいか
6. **検証ポイント**:誰がどこで何を検証するか(`state` の照合、PKCE の照合、ID トークンの `iss`/`aud`/`exp`/`nonce` 検証など)が図に現れているか
7. Mermaid として描画できる構文か

## 返し方

- 正しい図を丸ごと示さない
- 「抜けている」ものは、**どこに何が足りないかのヒント** に留める(例:「AS から Client へのリダイレクトの前に、AS が検証すべきことが 2 つある。何だと思う?」)
- 誤っている注記は、なぜ違うかを説明し、正しい理解を本人に言わせる
- 全観点を満たしていたら `PROGRESS.md` の「仕上げ」の該当項目にチェックを入れる
- 図 3(OIDC)では図 2 との差分が色分けされているか(`rect rgb(...)` など)も確認する
